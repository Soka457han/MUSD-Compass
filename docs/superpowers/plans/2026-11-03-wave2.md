# MUSD Compass Wave 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer the Wave 1 judge review: mainnet Borrow -> Earn with real hints, a "what to do" safety layer with top-up/repay, WalletConnect, and proof from outside users, all clearly labelled testnet vs mainnet.

**Architecture:** Keep the existing guard-simulate-send path (`web/src/lib/sendSafely.ts`) and make it chain-aware (testnet default, mainnet opt-in). Add pure, unit-tested libraries (`hints.ts`, `safety.ts`, `borrowEarn.ts`) and thin UI on top. WalletConnect plugs in as another EIP-1193 provider, so `connect(provider)` in `web/src/lib/wallet.ts` stays the single entry.

**Tech Stack:** Next.js 16, TypeScript, viem 2.57.11, Vitest, Playwright + axe, Python bot (pytest). New dependency: `@walletconnect/ethereum-provider` (exact version, at least two weeks old, pinned).

**Spec:** `docs/superpowers/specs/2026-11-03-wave2-design.md` (approved 3 Nov 2026). Judge review text is quoted in its Context section.

**Working rules:** run commands from `F:\snipping\musd-compass\web`. The user commits and pushes in GitHub Desktop, so each task ends at a "Checkpoint" that lists changed files; do not run `git commit` or `git push` unless the user asks. `.github/workflows/ci.yml` is protected from device writes.

## Global Constraints

- Compass has no contract of its own, no custody, no keys. Never ask for a seed phrase or private key; only public addresses appear in docs.
- Every write passes `guard()` then `simulateContract`, `estimateContractGas` x 1.2 (`gasWithBuffer`), then send and receipt.
- Approvals are the exact amount, only to the vault (sMUSD), never near `maxUint256`.
- Trove safety floor `SAFE_ICR = 2` (200%), Mezo minimum 110%. Borrow fee 0.1%, minimum net debt 1,800 MUSD, gas compensation 200 MUSD (read live, constants are fallbacks).
- Testnet (chain 31611) is the default. Mainnet writes are off unless `NEXT_PUBLIC_MAINNET_WRITES=1` AND the user confirms chain and amount on screen. Never present testnet transactions as mainnet usage.
- Mainnet allowlist: mainnet MUSD, sMUSD, BorrowerOperations (`openTrove`, plus `addColl` and `repayMUSD` only if Task 6 ships). Nothing else.
- Copy rules (humanizer): no em or en dashes, no "not X but Y", no bold labels in lists, no invented numbers, every number states its source or assumption.
- Phone first (360 px, no horizontal scroll), WCAG AA, axe clean on every page in light and dark.
- No secrets in git. `.env*` stays ignored except `.env.example`.
- Deadline: treat **13 Nov 2026** as the AKINDO Wave 2 deadline until confirmed (program text says build ends 15 Nov). Code freeze 11 Nov.

## Review Focus

1. Price moves between quote and signing, so the trove lands below the ICR floor: re-read price and re-check ICR at send time and refuse (Task 3).
2. Wallet is on the wrong chain (testnet UI, mainnet wallet or the reverse): the guard compares the wallet chain id with the action's chain and refuses a mismatch (Task 1).
3. Mainnet flag is off: no mainnet write button renders and `guard()` still refuses mainnet addresses (Task 1, Task 4).
4. Account already has a trove: `openTrove` would revert, so the UI offers top-up/repay instead of Open (Task 3, Task 6).
5. WalletConnect session is rejected, expires or the user closes the QR modal: a plain-English error and a working retry, no hung spinner (Task 7).
